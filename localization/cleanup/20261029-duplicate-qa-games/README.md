# Duplicate QA game cleanup

Scope: inactive, ignored `game/` payloads under `localization/probes/` and `localization/previews/` in the canonical Forest checkout. The owner requested unnecessary-file cleanup on 2026-10-29.

Only files whose complete SHA-256 and byte length equal a retained file are selected. Unique bytes stay in place. Source, translations, glossary, logs, screenshots, player files, code snapshots and all 22 protected complete game copies are excluded. The current build is also excluded as a mutable reference. No project directories or history records are deleted.

`scope.json` records exclusions. `plan.json` is the exact reconstruction map: each removed `path` has its own hash, size, original file identity and a `retainedCopy` with the same bytes. `retained-copies.json` lists all reconstruction sources; these files must survive any future cleanup. Earlier run receipts stay unchanged. Historical game folders affected by cleanup are now partial archives, not runnable installations.

For an explicitly needed historical run, select its missing paths from `plan.json`, verify each retained source SHA-256 and byte length, create the missing parent directories and copy the retained source to the exact missing path. Refuse existing destinations; recheck the restored hash. Do not relaunch a game or modify player files merely to reconstruct an archive. `reconstruction-verification.json` records the actual bounded restoration check and complete source-map verification.

`deletions.jsonl` records verified intent immediately before each unlink. Reconcile an interrupted operation from the immutable plan, retained sources, ledger and actual path presence; do not infer deletion solely from an intent row. The first execution was deliberately stopped by exact verified PID to replace per-file device flushes with batched ledger sync. The separately fsynced full plan preserves the reconstruction boundary; no file can be removed without its recorded retained source. `cleanup-v1.py` and `apply-v1-stop.json` preserve that execution version. A second measured bottleneck repeated 4,285 global open-path comparisons for every file; `cleanup-v2.py` and `apply-v2-stop.json` preserve it. The current recipe computes the equivalent exact game-root set once. `active-file-guard-verification.json` checks equivalence against the real inventory and matching positive/sibling-boundary controls. Continuations reconcile the same ledger and plan; prior deletions are never repeated.

`Result.json` reports total completed removals and logical bytes. Physical disk space is measured separately; APFS sharing and concurrent activity can make it differ. Source integration/build work remains a separate task; this cleanup does not establish localization acceptance.

Large operational ledgers are stored as verified lossless `.gz` copies to avoid retaining redundant plaintext. `compressed-ledgers.json` pins original and compressed hashes/lengths; full decompression equality passed before each plaintext was removed. To inspect the reconstruction map, read `plan.json.gz` through Python `gzip.open(..., "rt")` or decompress it first. Historical execution/verification scripts expect the original plaintext filenames; restore those exact files from the verified archives before any separately authorized reproduction. Completed receipts are immutable, not instructions to rerun cleanup.
