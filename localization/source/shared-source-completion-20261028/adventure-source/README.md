# Six compiled Adventure records

The static Adventure factory contains six records outside the BGDatabase Quest
display family. This supplement identifies 18 title/notification-title/body
operands and two overlay status prefixes as display sources. Twenty-four
gateway, spawn-area, save and completion-trigger operands stay exact. It is
source evidence for the same 30-locale repair, not target wording or a game patch.

The coordinator read all supplied complete factory/property, confirmation-page,
overlay and notification bodies. The original project-local DLL matches the
established original assembly SHA-256. The existing read-only inspector's source
and binary hashes are recorded. The original installed game and saves were not
accessed. Saved IL is immutable evidence, not a recursive renderer audit.

The factory constructs AdventureType 100/200/300/400/500/600 in order, each with
three display properties and four separate string identities. Titles and bodies
pass through unchanged backing fields/getters into AddAdventurePage, then the
SetTitle/SetBody child-TMP loops. Titles also enter the overlay's SetTitleText
loop; abandoned/completed visible-state branches prepend their own status text.
Notification titles enter queued types 7/8/9 and the corresponding switch paths
pass them to the three existing notification prefix/TMP methods. Movie/tutorial,
visible-state, chapter-select and cheat guards remain separate and unchanged.

The titles include Blessing of the Bells, Dungeons and Juices (two variants),
Mystery Meets, Season's Greetings and Lending a Paw. Their ornamental initial
markup must be adapted as complete titles, not translated fragments. Keep the
source puns and related glossary terms in their complete editorial groups. The
last body contains one actual LF, not a literal backslash+n; no unescaping or
normalization is performed. Source prose is stored from exact raw literal values.

`roster.jsonl` binds all 44 assembly/method/offset identities, exact values and
hashes, property roles and immediate consumers. `display-source.jsonl` and
`preserve-exactly.jsonl` partition the same ordered roster. `verification.json`
pins the original literal index and all saved consumer evidence. The full
factory has 42 string operands; the two other display operands are the overlay
status prefixes. No equal-value occurrence is deduplicated.

Check complete outputs:

```sh
python3 -B localization/source/shared-source-completion-20261028/adventure-source/verify.py
```

First creation uses `--write` and refuses existing outputs. All products are
prepared first; sequential exclusive writes do not form a transaction. A matching
positive control and changed-save-key control exercise exact identity
preservation even when the changed value's hash is internally consistent. This
does not simulate native rendering or persistence.

Actual event registration, selected live Adventure, fitting, typewriter/cache
coherence, target wording and runtime acceptance remain pending. The source
factory is not already covered by translated BG Quest rows or stored native
placeholder headings. No global source/editorial/renderer gate passes here.
