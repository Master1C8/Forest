# Forest localization process, revision 2

Russian development supplies verified mechanisms and regression examples. Russian
wording, font coverage, layout sizes, screenshots and acceptance are locale-specific
evidence. The owner has confirmed that the Russian localization is complete and
working. Its accepted build is the common implementation baseline. Historical
test/pending flags do not revoke that owner acceptance; retain their old records.
This binding applies the existing universal stages and editorial algorithm to
every Forest 0.45 locale; it adds no extra full semantic rereads.

## Current queue and existing work

`completion/process-spec.json` defines the finite shared tasks and source families.
`completion/locale-queue.json` is the current queue snapshot. Use
`python3 -B tools/locale_queue.py status` and `check` before continuation. The six
existing language jobs retain their identities, saved dialogue, custom corpus
helpers, holds, audit cycles and immutable execution versions. Their additive
`current-workflow.json` pointers select the new assignment. Historical group
submissions and job completion receipts are not rewritten as current activity.
The remaining configured target languages are planned, not newly authorized CLI
streams. At most six locale-owned streams, including Japanese, may run. The owner removed
the permanent technical stream on October 30, 2026. Parent alone owns Git/index operations.

`prepare --locale CODE --output PATH` prepares the first bounded reconciliation
packet. It does not launch a model. Use the existing job's directory for its new
packet; reconcile an occupied output instead of replacing or duplicating work.
The completion manifest is published last. Per-file atomic writes do not make
queue/pointer/packet publication a transaction. A missing manifest is partial work.
`check` verifies actual files and hashes; passing it is structural validity only.
After a real input/recipe change, use `update --reconcile` to preserve the old
queue, receipt and replaced pointers under `completion/queue-history/` before
publishing a refreshed snapshot. This does not rewrite saved translations or
accept old semantic/runtime evidence against new dependencies. Partial publication
remains explicit; reconcile it before another update or worker submission.

## Finite task selection

Game testing is the final verification stage. Finish the complete translation and
editing, then the universal independent editorial review and correction deltas.
Every shared text family must have an exact final translated/edited or justified
preserved disposition; unknown coverage and visible English artwork are unfinished,
not a default baseline exemption. Include all primary menu layers, image headings,
dynamic fragments and special scenes. Bind final resources and the complete package
to those exact accepted wording versions before gameplay, saves or native screenshots.
The common supervisor and explicit-locale native runner check
`python3 -B tools/locale_queue.py text-gate --locale CODE --json` before model/runtime
submission. This requires current version-bound translate-edit/editorial acceptance
and complete family translation/review coverage. Resource-only author/review tasks
and packaging are gated too, even when an inherited `executionStage` still says
translate-edit; work category, task class and resource packet identity determine
the downstream work. Text stages allow substantive wording/editing/source-disposition
review and their immediate deterministic safety checks, not separate resource/code
review or archive phases. A saved candidate, old owner runtime
authorization, preliminary dialogue passes or native-not-run flags cannot bypass it.
New tasks declare `executionStage`; child assignments inherit it unless explicitly
changed. Runtime authority remains deferred until this gate passes. Existing useful
captures remain evidence, not final acceptance. Regression: a saved candidate with
English Inventory/Active/Completed headings or unresolved text families does not start
another game test just because its resource readback and five local repairs passed.
Reconcile missing evidence through its pinned owning editorial manifest before
assigning another semantic review; calculation recovery is not new translation.
Only then present the exact remaining game test and obtain its applicable owner
instruction when it has not already been granted. Existing applicable permission
does not need to be requested again after the prerequisite gate passes. This ordering
grants no installer or publication authority.

Text readiness is distinct from final resource/native/style acceptance. After the
text gate passes, prepare and statically verify the final resources/package, then
run the authorized final game tests. Do not require a native-dependent font/style
or resource acceptance to pass before the very game test that establishes it.
Retained controls, exact symbols and accepted baseline preservation are separate
from untranslated phrases; resolve their actual version-bound dispositions in the
owning text evidence rather than manufacturing linguistic passes or inferring a
missing translation from raw held counters. Regression: an Item400 stored-only
caption or preserved ??? is not automatically an untranslated ordinary phrase.
Regression: a ready static payload coexists with current unaccepted text versions;
recover valid archived reviews and finish the actual remaining editorial work
before proposing a game launch.

First reconcile each existing locale's real corpus, custom adapter, glossary,
editorial manifests and unresolved groups. Do not restart its completed draft.
Every next assignment names one finite artifact, source selectors, dependencies,
write scope, predicate and stop condition. Source-held selectors cannot enter an
application allowlist. A source/renderer blocker does not erase independent saved
work, and a preliminary exception never becomes whole-game acceptance.

Local completion is autonomous within the current locale authorization. Missing
receipt pointers, recoverable source/target data, locale configuration and permitted
local tool repairs are work, not owner decisions. Before declaring static work
exhausted, trace every proposed blocker to its owning current source/target,
consumer or permission boundary. Historical unresolved counts and null hashes are
not evidence of a protected-source question. Reuse the accepted Russian selection
and preservation behavior, retaining every genuine target difference and review.
Regression: a historical257-row receipt index has null source/target versions;
recover and bind the actual family inputs before asking the owner to resolve257
supposed source decisions. Recovery alone adds no semantic coverage.

Normal finite work returns `continue` with its concrete next task. If a result is
mistakenly labelled `blocked` but explicitly declares `localWorkReady:true`, its
next work/review task must name `workCategory` as locale-content, locale-resource
or local-tool-repair and nonempty exact `entryPins`. The supervisor verifies those
inputs and applies all ordinary progress, ownership, independent-review and
no-repeat guards before continuing. Unready conditional/native tasks never gain
authority from this flag. Real owner decisions, protected source changes,
unauthorized game/runtime actions and external failures remain explicit stops.
`tools/launch_locale_repair.py --terminal-config CONFIG` prepares a new pinned
execution for named blocked lanes without a live observer handoff or rewriting
unselected lanes. A saved submission intent must be reconciled, never resubmitted.

The coordinator resolves a named shared consumer/adaptation defect once and must
not recursively trace another framework method without a named game predicate.
Reuse source/method/resource evidence by fingerprint. Linguistic lanes author and
review their own wording only after its applicable gates; they do not each reverse

## Required regression surfaces from Russian development

- Dialogue and all display overrides: temporary speaker labels, active/dormant
  greetings, inventory, notifications, journal, chapter/gallery, Bio, input,
  counters, narrative pages, Adventures, Lantern and content-completion screens.
- Haiku: stable choice identities, all 27 combinations, three named and 24 mixed
  endings. Keep evaluation keys distinct from displayed translations; verify
  locale casing such as Turkish. CLR checks leave real callbacks unverified.
- Generated text: exact dynamic fragments/separators, CR versus LF, the glitch
  fragment workload, placeholders, counters, entered values and reveal timing.
- Rendering: native Text versus TMP, every face/glow/preferred-size member,
  atlas growth under the complete workload, actual fallback/material ownership,
  small labels and assembled output. Derive sizes from the target language.
- Preservation: independent 51,572-state BG readback, unchanged nonselected
  objects/method bodies, all 1,385 original textures and resource streams,
  original bundle compression/CAB identity and Addressables CRC/size.
- Package updates: explicit old/new/unknown states, required companion versions,
  interruption between writes, recovery, exact postconditions after first apply,
  unchanged repeat and running-game rejection. Atomic file writes are not a
  multi-file transaction. Never overwrite the owner's protected test copy.
- QA validity: original pause entry, real event subscribers, actual camera
  geometry, nonempty loaded workload and exact fixture restoration. An invalid
  harness is repaired at its failing boundary instead of blamed on translation.
- Storage: immutable later-read dependency closures, small overlays/read-only
  inputs, original compression and at least 5 GiB reserve before full builds.
  Retain unique evidence and reconstruction anchors; no blanket cleanup by name.

## Fresh CLI execution and reporting

For current percentages, run `python3 -B tools/locale_queue.py progress`.
This is a deterministic view of the owning jobs, not the historical v2 `status`
snapshot. [Completion-index rules](completion/PROGRESS.md) define the single fixed
100-point policy, source/version bindings, real receipt requirements and separate
release gates. Unknown work is never silently removed from the denominator;
calculation/scope revisions are recorded as rebases, not production progress.

Use only explicitly selected gpt-6.1-sol/high/OpenAI, ignoring user defaults.
Verify actual fresh runtime metadata and argv before localized input. Never use
Astra, fallback, resume/fork history, nested jobs or additional model streams.
Load bounded mandatory instructions and the complete compact working glossary
once. Read exact source/target/context, not prior chats or unrelated audits.

The frozen efficiency helper exposes `readingView.readingPages` for new review
packets. Read this complete representation instead of printing both the archive
and the original packets. It preserves every row and all wording, IDs, context,
flags, nested objects and unknown fields; only recognized top-level SHA-256 and
original-packet provenance move out of the reading representation. The separately
hashed lossless archive retains those exact values for deterministic verification
and named discrepancies. Both representations are checked against frozen inputs;
neither grants semantic coverage. Old active packets keep their frozen helper.
Regression: a source-context packet with repeated hash/provenance fields exposes
every source and target plus null/false/zero, CR/LF, Unicode and unknown context in
the reading pages; changing either representation rejects before review input.

Each phase saves substantive evidence before continuing. Unknown submission
outcomes, capacity errors and interrupted observers require reconciliation by job,
thread/process identity and immutable inputs; no automatic duplicate/retry loop.
An unchanged blocker is a stop condition, not another framework-tracing task.

Keep deterministic application, readback, packaging and receipt publication in
the substantive owning assignment. They are not separate model-review phases.
The locale-owned dispatch guard runs before phase creation and model submission.
A separate resource reviewer must name a new semantic, consumer, code or font-role
judgment and pin its exact inputs in `newJudgment`; copying already reviewed wording
and checking exact bytes alone does not qualify. A deferred task stays in its own
lane, without an inbox or technical worker. This does not waive actual independent
semantic/code review or native gates. Regression: one reviewed Finley quest sentence
is applied and fully read back in the same substantive batch; an additional model
request solely to affirm that identical saved value is rejected before submission.

own reviewed wording and explicit locale parameters. There is no permanent
