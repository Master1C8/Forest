# Forest localization process, revision 2

Russian development supplies verified mechanisms and regression examples. Russian
wording, font coverage, layout sizes, screenshots and acceptance are locale-specific
evidence. The owner has confirmed that the Russian localization is complete and
working. Its accepted build is the common implementation baseline. Historical
test/pending flags do not revoke that owner acceptance; retain their old records.
This binding applies the existing universal stages and editorial algorithm to
every Forest 0.45 locale; it adds no extra full semantic rereads.

## Current queue and existing work

`completion/process-spec.json` defines the finite shared tasks and source families.
`completion/locale-queue.json` is the current queue snapshot. Use
`python3 -B tools/locale_queue.py status` and `check` before continuation. The six
existing language jobs retain their identities, saved dialogue, custom corpus
helpers, holds, audit cycles and immutable execution versions. Their additive
`current-workflow.json` pointers select the new assignment. Historical group
submissions and job completion receipts are not rewritten as current activity.
The remaining configured target languages are planned, not newly authorized CLI
streams. At most six linguistic streams, including Japanese, and one separate
technical stream may run when authorized. Parent alone owns Git/index operations.

`prepare --locale CODE --output PATH` prepares the first bounded reconciliation
packet. It does not launch a model. Use the existing job's directory for its new
packet; reconcile an occupied output instead of replacing or duplicating work.
The completion manifest is published last. Per-file atomic writes do not make
queue/pointer/packet publication a transaction. A missing manifest is partial work.
`check` verifies actual files and hashes; passing it is structural validity only.
After a real input/recipe change, use `update --reconcile` to preserve the old
queue, receipt and replaced pointers under `completion/queue-history/` before
publishing a refreshed snapshot. This does not rewrite saved translations or
accept old semantic/runtime evidence against new dependencies. Partial publication
remains explicit; reconcile it before another update or worker submission.

## Finite task selection

First reconcile each existing locale's real corpus, custom adapter, glossary,
editorial manifests and unresolved groups. Do not restart its completed draft.
Every next assignment names one finite artifact, source selectors, dependencies,
write scope, predicate and stop condition. Source-held selectors cannot enter an
application allowlist. A source/renderer blocker does not erase independent saved
work, and a preliminary exception never becomes whole-game acceptance.

The technical lane resolves shared consumer/adaptation requirements once. It must
not recursively trace another framework method without a named game predicate.
Reuse source/method/resource evidence by fingerprint. Linguistic lanes author and
review their own wording only after its applicable gates; they do not each reverse
engineer the same engine. Do not automatically reread unrelated accepted units.

For new narrative150 and haiku27 resource deliveries, use the common
`tools/locale_resources.py` entry point and pinned data-only locale profiles in
[resource-profiles/README.md](resource-profiles/README.md). Add locale data and
version-matching receipts, not another per-language builder. Accumulate disjoint
reviewed packets without rereading unchanged wording. Preserve existing running
jobs and frozen helpers; adopt this interface at the next applicable resource
assignment, without interrupting an unrelated phase or adding a planning-only
phase. Other shared mechanisms retain their existing owners and gates.

Resolve shared dependencies through `python3 -B tools/locale_dependencies.py`
and [the Russian-reference integration](completion/russian-reuse-20261030-01/README.md).
The current progress report consumes exact independently accepted receipts and
parent source-policy overlays; an old blocked result or historical `pending`
author manifest must not reopen completed unchanged work. Reuse matching Russian
mechanisms once for all locales. New locale wording, resource/native acceptance
and held consumers remain separate. A changed canonical source version or lane
result invalidates its old blocker overlay. Keep immutable execution inputs intact.

The current owner confirmation is recorded in
`completion/russian-owner-baseline-20261030-01/acceptance.json`. Reuse the accepted
Russian build's actual source/display/evaluation behavior and selection policies.
Do not require another global source/framework audit before porting those same
mechanisms. Work on concrete target-locale differences: reviewed wording, adapter
configuration, font/glyph resources and target layout/runtime checks. Russian
acceptance does not grant another locale's semantic or rendering pass.

An explicit owner request to repair/resume a stopped lane uses a pinned finite
`ownerResume` assignment and owner authorization, as recorded in
`completion/resume-stopped-20261030-01/`. It does not wait for a historical global
source wake or change old gate files. Use the shared repair launcher with its
`--continuation-config`; the old default source-wake launch is rejected after
Russian owner acceptance. Preserve active children through the verified observer
handoff and verify actual fresh runtime before target input. Unchanged blockers
without new work/authority still launch nothing.

The family catalog deliberately includes overlapping physical copies and repeated
glow fields. Family counts cannot be summed into a unique visible-string total.
Equal English text, a matching filename or a Russian acceptance receipt is not a
locale target decision. Console/debug text needs an actual presentation decision.
Retain the narrative Mouse/Penny holds, paused menu holds, ornamental constraints
and other per-selector decisions until their owning gate accepts them.

## Required regression surfaces from Russian development

- Dialogue and all display overrides: temporary speaker labels, active/dormant
  greetings, inventory, notifications, journal, chapter/gallery, Bio, input,
  counters, narrative pages, Adventures, Lantern and content-completion screens.
- Haiku: stable choice identities, all 27 combinations, three named and 24 mixed
  endings. Keep evaluation keys distinct from displayed translations; verify
  locale casing such as Turkish. CLR checks leave real callbacks unverified.
- Generated text: exact dynamic fragments/separators, CR versus LF, the glitch
  fragment workload, placeholders, counters, entered values and reveal timing.
- Rendering: native Text versus TMP, every face/glow/preferred-size member,
  atlas growth under the complete workload, actual fallback/material ownership,
  small labels and assembled output. Derive sizes from the target language.
- Preservation: independent 51,572-state BG readback, unchanged nonselected
  objects/method bodies, all 1,385 original textures and resource streams,
  original bundle compression/CAB identity and Addressables CRC/size.
- Package updates: explicit old/new/unknown states, required companion versions,
  interruption between writes, recovery, exact postconditions after first apply,
  unchanged repeat and running-game rejection. Atomic file writes are not a
  multi-file transaction. Never overwrite the owner's protected test copy.
- QA validity: original pause entry, real event subscribers, actual camera
  geometry, nonempty loaded workload and exact fixture restoration. An invalid
  harness is repaired at its failing boundary instead of blamed on translation.
- Storage: immutable later-read dependency closures, small overlays/read-only
  inputs, original compression and at least 5 GiB reserve before full builds.
  Retain unique evidence and reconstruction anchors; no blanket cleanup by name.

## Fresh CLI execution and reporting

For current percentages, run `python3 -B tools/locale_queue.py progress`.
This is a deterministic view of the owning jobs, not the historical v2 `status`
snapshot. [Completion-index rules](completion/PROGRESS.md) define the single fixed
100-point policy, source/version bindings, real receipt requirements and separate
release gates. Unknown work is never silently removed from the denominator;
calculation/scope revisions are recorded as rebases, not production progress.

Use only explicitly selected gpt-6.1-sol/high/OpenAI, ignoring user defaults.
Verify actual fresh runtime metadata and argv before localized input. Never use
Astra, fallback, resume/fork history, nested jobs or additional model streams.
Load bounded mandatory instructions and the complete compact working glossary
once. Read exact source/target/context, not prior chats or unrelated audits.

The frozen efficiency helper exposes `readingView.readingPages` for new review
packets. Read this complete representation instead of printing both the archive
and the original packets. It preserves every row and all wording, IDs, context,
flags, nested objects and unknown fields; only recognized top-level SHA-256 and
original-packet provenance move out of the reading representation. The separately
hashed lossless archive retains those exact values for deterministic verification
and named discrepancies. Both representations are checked against frozen inputs;
neither grants semantic coverage. Old active packets keep their frozen helper.
Regression: a source-context packet with repeated hash/provenance fields exposes
every source and target plus null/false/zero, CR/LF, Unicode and unknown context in
the reading pages; changing either representation rejects before review input.

Each phase saves substantive evidence before continuing. Unknown submission
outcomes, capacity errors and interrupted observers require reconciliation by job,
thread/process identity and immutable inputs; no automatic duplicate/retry loop.
An unchanged blocker is a stop condition, not another framework-tracing task.

Resource dependencies use the shared protocol in
[the process repair contract](completion/process-repair-20261030-02/config.json).
The coordinator repairs scheduling and verifies evidence; the existing language
lanes own target wording and the single technical lane owns shared engineering.
A stopped language lane resumes its own exact finite task only after all required
request versions have actual saved resource outputs and a complete clean distinct
review. The observer publishes immutable ready receipts, rechecks input/output
hashes and consumes each new version once. Quiet dependency waiting makes no model
requests or unchanged status writes. An absent next task never creates work.

The observer now enforces ownership before creating a paid phase. Language author
tasks require `taskClass: linguistic-work`; explicit resource/data-binding review
packets and unclassified work are deferred as `held-dispatch-policy` and routed
once to the existing technical inbox. This preserves their completed owning result
without launching another language model for metadata. The observer's verified
dependency-consumption path remains admitted; a worker-supplied receipt field alone
does not bypass dispatch. Mechanical target binding, manifests, retained-receipt
wrapping and hash checks use the shared implementation. Review new engineering
decisions together with the actual composed artifact, preserving every genuinely
unreviewed wording/context requirement. Read active assignments to their existing
bounded completion; do not interrupt/replay them to retrofit this rule.

Dispatch routing has a stable directory across observer handoffs. A hold document
and its inbox envelope are individually atomic, with no cross-file transaction.
Resume the same verified partial publication after interruption; a changed partial
or unknown version is an error, never a reason to create another model request.
Regression: a language worker proposes a resource-binding review or another
unclassified data-transport author task. Preserve the completed phase, publish one
routing correction and create no new model phase, including after handoff/replay.

Preserve both historical `id` and `requestId` request formats through the same
identity reader. Always finalize a successfully adopted worker's result hash,
summary and review coverage before a terminal return. Verified legacy metadata
omissions are journal repairs, not grounds for repeating the completed model turn.
Use `tools/reconcile_locale_terminal.py` only for its verified idle terminal
startup-error scope; retain its immutable before/after repair plan and resume that
same plan after interruption between files. No cross-file transaction is claimed.

Regression: two required deliveries exist only as drafts, then only one has a
clean review. The language model must remain asleep. Publish the second exact
reviewed delivery and continue the prepared task once; reject changed profile or
resource bytes and never publish producer receipts from the consumer. A handoff
of a live worker that later returns blocked must retain its result and usage,
without rerunning it or leaving a missing result hash in terminal state.

Report the same universal stages for every language with passed / failed /
not-run / needs-review / not-applicable, concrete artifacts and remaining action.
Keep dialogue IDs, physical occurrences, additional-family coverage, editorial,
fonts, package, native visuals and release separate. Report actual worker and
orchestration usage with cached input and reasoning as subsets, unknown counters
as unknown. No new requests or token estimates are created by this queue update.
