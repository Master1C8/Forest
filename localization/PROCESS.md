# Forest localization process, revision 2

Russian development supplies verified mechanisms and regression examples. Russian
wording, font coverage, layout sizes, screenshots and acceptance are locale-specific
evidence. The Russian delivery is an owner test build, not a complete release.
This binding applies the existing universal stages and editorial algorithm to
every Forest 0.45 locale; it adds no extra full semantic rereads.

## Current queue and existing work

`completion/process-spec.json` defines the finite shared tasks and source families.
`completion/locale-queue.json` is the current queue snapshot. Use
`python3 -B tools/locale_queue.py status` and `check` before continuation. The six
existing language jobs retain their identities, saved dialogue, custom corpus
helpers, holds, audit cycles and immutable execution versions. Their additive
`current-workflow.json` pointers select the new assignment. Historical group
submissions and job completion receipts are not rewritten as current activity.
The remaining configured target languages are planned, not newly authorized CLI
streams. At most six linguistic streams, including Japanese, and one separate
technical stream may run when authorized. Parent alone owns Git/index operations.

`prepare --locale CODE --output PATH` prepares the first bounded reconciliation
packet. It does not launch a model. Use the existing job's directory for its new
packet; reconcile an occupied output instead of replacing or duplicating work.
The completion manifest is published last. Per-file atomic writes do not make
queue/pointer/packet publication a transaction. A missing manifest is partial work.
`check` verifies actual files and hashes; passing it is structural validity only.
After a real input/recipe change, use `update --reconcile` to preserve the old
queue, receipt and replaced pointers under `completion/queue-history/` before
publishing a refreshed snapshot. This does not rewrite saved translations or
accept old semantic/runtime evidence against new dependencies. Partial publication
remains explicit; reconcile it before another update or worker submission.

## Finite task selection

First reconcile each existing locale's real corpus, custom adapter, glossary,
editorial manifests and unresolved groups. Do not restart its completed draft.
Every next assignment names one finite artifact, source selectors, dependencies,
write scope, predicate and stop condition. Source-held selectors cannot enter an
application allowlist. A source/renderer blocker does not erase independent saved
work, and a preliminary exception never becomes whole-game acceptance.

The technical lane resolves shared consumer/adaptation requirements once. It must
not recursively trace another framework method without a named game predicate.
Reuse source/method/resource evidence by fingerprint. Linguistic lanes author and
review their own wording only after its applicable gates; they do not each reverse
engineer the same engine. Do not automatically reread unrelated accepted units.

The family catalog deliberately includes overlapping physical copies and repeated
glow fields. Family counts cannot be summed into a unique visible-string total.
Equal English text, a matching filename or a Russian acceptance receipt is not a
locale target decision. Console/debug text needs an actual presentation decision.
Retain the narrative Mouse/Penny holds, paused menu holds, ornamental constraints
and other per-selector decisions until their owning gate accepts them.

## Required regression surfaces from Russian development

- Dialogue and all display overrides: temporary speaker labels, active/dormant
  greetings, inventory, notifications, journal, chapter/gallery, Bio, input,
  counters, narrative pages, Adventures, Lantern and content-completion screens.
- Haiku: stable choice identities, all 27 combinations, three named and 24 mixed
  endings. Keep evaluation keys distinct from displayed translations; verify
  locale casing such as Turkish. CLR checks leave real callbacks unverified.
- Generated text: exact dynamic fragments/separators, CR versus LF, the glitch
  fragment workload, placeholders, counters, entered values and reveal timing.
- Rendering: native Text versus TMP, every face/glow/preferred-size member,
  atlas growth under the complete workload, actual fallback/material ownership,
  small labels and assembled output. Derive sizes from the target language.
- Preservation: independent 51,572-state BG readback, unchanged nonselected
  objects/method bodies, all 1,385 original textures and resource streams,
  original bundle compression/CAB identity and Addressables CRC/size.
- Package updates: explicit old/new/unknown states, required companion versions,
  interruption between writes, recovery, exact postconditions after first apply,
  unchanged repeat and running-game rejection. Atomic file writes are not a
  multi-file transaction. Never overwrite the owner's protected test copy.
- QA validity: original pause entry, real event subscribers, actual camera
  geometry, nonempty loaded workload and exact fixture restoration. An invalid
  harness is repaired at its failing boundary instead of blamed on translation.
- Storage: immutable later-read dependency closures, small overlays/read-only
  inputs, original compression and at least 5 GiB reserve before full builds.
  Retain unique evidence and reconstruction anchors; no blanket cleanup by name.

## Fresh CLI execution and reporting

Use only explicitly selected gpt-6.1-sol/high/OpenAI, ignoring user defaults.
Verify actual fresh runtime metadata and argv before localized input. Never use
Astra, fallback, resume/fork history, nested jobs or additional model streams.
Load bounded mandatory instructions and the complete compact working glossary
once. Read exact source/target/context, not prior chats or unrelated audits.

Each phase saves substantive evidence before continuing. Unknown submission
outcomes, capacity errors and interrupted observers require reconciliation by job,
thread/process identity and immutable inputs; no automatic duplicate/retry loop.
An unchanged blocker is a stop condition, not another framework-tracing task.

Report the same universal stages for every language with passed / failed /
not-run / needs-review / not-applicable, concrete artifacts and remaining action.
Keep dialogue IDs, physical occurrences, additional-family coverage, editorial,
fonts, package, native visuals and release separate. Report actual worker and
orchestration usage with cached input and reasoning as subsets, unknown counters
as unknown. No new requests or token estimates are created by this queue update.
