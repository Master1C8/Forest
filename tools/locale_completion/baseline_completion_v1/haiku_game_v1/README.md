# Full-game haiku identity adapter

This version reuses the accepted Russian adapter's exact `AddHelpers`, guard,
predicate extraction and whole-tree/reversal mechanisms. Locale, culture, mapping,
supported candidate hash and private helper prefix are explicit settings. It does
not copy Russian target wording. `build.py --root ROOT --profile PROFILE --output
OUTPUT` saves a new actual game candidate through the shared resource publisher;
`--mode check` verifies the published bytes without rebuilding.

The game assembly is read as Cecil data only. The consumer test loads isolated
fixtures extracted from the actual serialized output, replacing Unity, UI,
services, callback storage and timing at the documented original boundary. All
27 products run in three cultures; nine exact full-source resolution results,
case/space/context/slot/null/fallback controls and pre-short-circuit validation
are distinct from native acceptance. Structural controls include changed branch,
trigger, comparison and timing and partial/repeated patch guards. Every original
metadata/body entry is compared; only nine same-width loads in one original
method change. Removing four private helpers and restoring those actual saved
loads must reproduce the entire preceding DLL byte for byte.

`read_resources.py` checks the actual two resource occurrences and six individual
template seeds using an explicit pinned Unity reader environment. It verifies
stable choice IDs, text, source-to-target control parity, outgoing links and
seed/controller/line-object bindings. A corpus also contains non-wording rows;
seed selection uses `row.get('source')`, preserving those rows instead of
requiring every inventory row to have a source string. Regression: all six seeds
are found in the full mixed inventory, all 18 choice occurrences match, and a
missing member, mismatched slot object or changed version rejects. It does not
infer that a serialized alpha of zero proves invisible native frames.

Compiler source, map, settings, original assembly and candidate input are frozen
under the fresh work directory before compilation. Profiles pin all read inputs
and the shared publisher. Existing output paths reject. Publisher output writes
are sequential with the manifest last; they are not a multi-file transaction.
The backend writes rollback, candidate, reversal, ledger and receipt separately.
Any interrupted output requires reconciliation before reuse; no automatic retry,
installation, source edit or game launch is part of this helper.
