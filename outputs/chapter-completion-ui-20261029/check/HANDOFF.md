## Failure, restoration and commit boundaries

launch-intent.json is written BEFORE Popen; launch.json records the launcher.
A timeout has unknown readiness, not proof of process exit. Observe the same run;
adopt a known surviving native process with the frozen chapter_gallery_process.py
only after startup-state says ready and its exact command/start identity matches.
Never restart the bottle, broad-kill a process or duplicate an unknown launch.

Each command records exact action/log offset/process identity. Incomplete tails
and prefix lookalikes are not ACKs. After timeout use the SAME receipt:

```sh
"$chapter_python" -B "$chapter_run/cg-helpers/capture_chapter_completion_ui.py" reconcile --run "$chapter_run" --receipt "$chapter_run/cc-command-receipts/EXISTING.json"
```

An unknown pending request blocks subsequent commands, including quit/restoration.
Known failure allows restoration or normal quit. Incomplete capture is preserved;
no automatic replay/resume is implemented. For an incomplete run, after reconciling
unknown outcomes, cleanup (not complete) normally quits the exact owned game,
waits up to60s, then requires no remaining task-executable sidecars/process rows:

```sh
"$chapter_python" -B "$chapter_run/cg-helpers/capture_chapter_completion_ui.py" cleanup --run "$chapter_run"
```

under cc-post-runtime BEFORE restoring the localized DLL/removing only the pinned
